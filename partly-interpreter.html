How it's built

Architecture delivering accuracy at scale.

Interpreter is a multi-modal model that processes technical diagrams, damage photographs, and natural language. The training stack is what makes it work — not the model alone.

// 01

Curated training data

Sourced from government records and licensed manufacturer data. Augmented with original research — structured vehicle teardowns and expert analysis Partly conducted in-house.

// 02

Purpose-built annotation

Generic labelling tools can't handle the complexity of parts data. Partly built its own annotation software — designed for assembly hierarchies, variant resolution, and fitment logic.

// 03

Expert labelling

Training data is annotated by experienced parts interpreters with decades of industry knowledge. Every label is verified against deployed production data before training.

What it delivers

Standardised, precise, and complete.

Interpreter resolves the three problems every parts query runs into: messy data, ambiguous fitment, and incomplete context. One model. Three guarantees.

// 01 · standardised

A universal standard across manufacturers.

Every manufacturer structures their catalogue differently. Interpreter resolves them into a single standard — how vehicles break down into assemblies, how parts within assemblies are grouped, and how they're named.

Access

Wherever you build, Interpreter is the engine.

Interpreter powers every Partly product, and is also available directly via API for the teams building on top of the world's parts data.

$curl -X POST https://api.partly.com/v1/identify \
-H "Authorization: Bearer $PARTLY_KEY" \
-d '{"vin": "JTMA1RFV0MD074921",
"damage": ["front-left"]}'
# response

{ "id": "part.front_bumper.cover",
